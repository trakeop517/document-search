# Поиск документов

Небольшой сервис на FastAPI, который ищет документы по тексту и позволяет удалять их по ID. Полные данные хранятся в PostgreSQL, а для поиска используется Elasticsearch, обращения к обоим хранилищам выполняются асинхронно

## Запуск

Для запуска нужны Docker и Docker Compose v2. На Windows можно использовать Docker Desktop с Linux-контейнерами. Все команды ниже выполняются из главной(коренной) папки проекта в PowerShell

Создайте файл `.env` в корне проекта:

```dotenv
POSTGRES_DB=documents
POSTGRES_USER=search
POSTGRES_PASSWORD=ваш_пароль_от_БД
ELASTICSEARCH_INDEX=documents
APP_PORT=8002
```

Исходные данные уже находятся в репозитории в файле `data/posts.csv`, но при необходимости CSV можно повторно скачать по [ссылке](https://disk.yandex.ru/d/UYooXd9q2yqTMQ)

Запустите Docker Desktop, дождитесь его готовности и выполните:

```powershell
docker compose up -d --build
docker compose ps
```

Когда все три контейнера получат статус `healthy`, создайте таблицу, поисковый индекс и загрузите документы:

```powershell
docker compose exec app python -m app.init_db
docker compose exec app python -m app.init_index
docker compose exec app python -m app.import_data
```

В исходном CSV находится 1500 документов, и после импорта они будут сохранены в PostgreSQL и Elasticsearch

Приложение доступно по адресу http://localhost:8002. PostgreSQL и Elasticsearch работают внутри сети Compose, их порты на хост не публикуются

Для обычной остановки используйте `docker compose stop`. Данные сохранятся, а запустить сервисы снова можно командой `docker compose up -d`. После изменения кода приложения потребуется пересборка:

```powershell
docker compose up -d --build app
```

## API и документация

Посмотреть документацию и выполнить запросы можно через Swagger по адресу http://localhost:8002/docs.

Для поиска используется `GET /search?q=текст`. Сервис ищет совпадения в Elasticsearch, получает полные документы из PostgreSQL и возвращает не больше 20 результатов, сами результаты отсортированы по дате создания от новых к старым, а при одинаковых датах по ID от большего к меньшему

Каждый результат содержит `id`, `rubrics`, `text` и `created_date`, если случается такое, что совпадений нет, то возвращается пустой список. Отсутствующий параметр `q`, пустая строка или же строка из пробелов возвращают ошибку `422`

Для удаления используется `DELETE /documents/{document_id}`. Документ удаляется из PostgreSQL и Elasticsearch. При успешном удалении возвращается `204` без тела ответа, если документа нет в обоих хранилищах, возвращается `404`. Некорректный ID возвращает `422`, а ошибка хранилища при удалении возвращает `503`

Метод `GET /health` возвращает `{"status": "ok"}`. Он проверяет только ответ приложения, а не подключения к хранилищам

В корне проекта находится `docs.json` с документацией в формате OpenAPI. После изменения API его можно обновить:

```powershell
Invoke-WebRequest -UseBasicParsing -Uri "http://localhost:8002/openapi.json" -OutFile .\docs.json
```

## Тесты

Функциональные тесты запускаются в отдельном Docker Compose-проекте со своими PostgreSQL и Elasticsearch. Они используют БД и индекс `documents_test`, поэтому рабочие документы не затрагиваются, также перед каждым тестом создаются тестовые данные, после него они очищаются

Чтобы не держать два Elasticsearch одновременно, сначала остановите рабочие контейнеры, затем запустите тесты:

```powershell
docker compose stop
docker compose -p document-search-tests -f compose.test.yaml up --build --abort-on-container-exit --exit-code-from tests
```

Тесты проверяют ответ приложения, подключения к хранилищам, поиск, сортировку, ограничение выдачи, некорректные запросы и удаление. Ожидаемый результат для текущего набора: `11 passed`. Предупреждение Starlette о `BlockingPortal` не означает провал тестов

После завершения удалите тестовое окружение и при необходимости снова запустите рабочее приложение:

```powershell
docker compose -p document-search-tests -f compose.test.yaml down --volumes
docker compose up -d
```

Удаление томов здесь относится только к отдельному тестовому проекту. Для рабочего проекта не используйте `docker compose down --volumes`, если хотите сохранить данные

## Особенности

ID назначаются по порядку записей CSV. Повторный импорт того же файла не создаёт дубликаты, но обновляет документы и восстанавливает ранее удалённые записи, но если изменить порядок строк, то соответствие ID документам изменится. Импорт также не удаляет документы, которых больше нет в файле

Между PostgreSQL и Elasticsearch нет общей транзакции, поэтому при частичном сбое данные могут разойтись. После устранения ошибки можно повторить импорт того же CSV или запрос удаления

Поиск собирает все найденные ID в память, что подходит для исходного набора из 1500 документов. Для большого объёма данных этот подход потребуется пересмотреть. Проект рассчитан на локальный запуск, аутентификация не настроена
